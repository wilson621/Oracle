# Purpose

The Oracle Design System defines the visual language of Oracle.

Its purpose is to ensure every screen, component and interaction feels like part of one coherent intelligence platform.

The design system prioritises clarity, consistency and confidence over decoration.

Oracle should always feel like Mission Control.

Never like a traditional gaming website.

---

# Design Philosophy

Oracle is an intelligence platform.

Its interface should reflect that identity.

Every screen should communicate:

Understanding

Evidence

Confidence

Precision

Professionalism

Operators should feel like they are interacting with an elite intelligence system rather than a conventional application.

---

# Visual Identity

Oracle combines inspiration from:

Mission Control

Intelligence Operations Centres

Military Briefings

Professional Data Platforms

Premium Software

Oracle avoids:

Neon cyberpunk

Overly aggressive gaming aesthetics

Excessive RGB styling

Visual clutter

Unnecessary animations

Premium is achieved through restraint.

---

# Core Design Principles

## Clarity Before Decoration

Every visual element should communicate information.

Decorative elements should never compete with intelligence.

---

## Hierarchy Before Density

The most important information should always be immediately visible.

Every screen should naturally guide the Operator's attention.

---

## Evidence Before Statistics

Present conclusions first.

Support them with evidence.

Support evidence with statistics.

Never reverse this order.

---

## Premium Before Flashy

Whitespace.

Typography.

Spacing.

Animation.

Hierarchy.

These create premium experiences.

Not excessive visual effects.

---

# Layout Philosophy

Every page should answer one question.

Operator

Who am I as a player?

Coach

What should I improve next?

Loadouts

What should I use?

Reports

How am I evolving?

Memory

What has Oracle learned?

Dashboard

What is most important today?

If a page cannot answer one primary question, its layout should be reconsidered.

---

# Information Hierarchy

Every screen should present information using three levels.

## Level One

Mission Critical

Examples:

Oracle Assessment

Recommendations

Mission Status

Operator Readiness

Confidence

These elements dominate the screen.

---

## Level Two

Operational Intelligence

Examples:

Behaviour Analysis

Weapon Intelligence

Movement

Decision Making

Positioning

Performance Trends

These support Level One decisions.

---

## Level Three

Supporting Evidence

Examples:

Charts

Statistics

Historical Sessions

Timelines

Graphs

Detailed Metrics

Evidence supports conclusions.

Not the other way around.

---

# Typography

Typography should communicate confidence.

Use typography to establish hierarchy rather than decoration.

Large headings communicate operational context.

Medium headings define intelligence sections.

Body text explains reasoning.

Small text supports evidence.

Avoid unnecessary font variations.

---

# Colour Philosophy

Colours communicate state.

Never decoration.

Primary Background

Near-black.

Neutral charcoal (formerly deep blue-black -- retired for the same reason
as Oracle Cyan: it read as a colour choice rather than a neutral. See
docs/Brand-Bible.md > Colour Philosophy > Oracle Teal).

Primary Accent

Oracle Teal (formerly Oracle Cyan -- see docs/Brand-Bible.md > Colour Philosophy)

Used sparingly.

Positive

Green

Warning

Amber

Critical

Red

Neutral

Grey

Accent colours should draw attention to intelligence.

Never overwhelm the interface.

---

# Spacing

Whitespace is an interface component.

Spacing communicates hierarchy.

Crowded layouts reduce perceived quality.

Every page should breathe.

---

# Component Standards

Components should be reusable.

Each component should perform one responsibility.

Current reusable components include:

OracleCard

MetricCard

StatusPill

ConfidenceRing

AnimatedNumber

SkillBar

MissionCard

Future components should extend the existing system.

Never duplicate it.

# Intelligence Components

Oracle introduces specialised interface components.

Oracle Assessment

Mission Brief

Intelligence Signal

# Motion

Motion supports understanding.

Examples:

Loading states

Transitions

Mission completion

Progress updates

Confidence changes

Motion should never distract.

Animations should feel deliberate.

Not playful.

---

# Icons

Icons reinforce hierarchy.

Icons should support meaning.

Not replace text.

Use consistent iconography across the platform.

---

# Status System

Oracle communicates status consistently.

Operational

🟢 Active

🟡 Monitoring

🟠 Warning

🔴 Critical

Development

✅ Complete

🟢 Active

🟡 Planned

🔵 Future

Every status should have one meaning throughout the platform.

---

# Oracle Language

The interface should consistently use Oracle terminology.

Preferred:

Operator

Oracle Session

Mission

Assessment

Recommendation

Confidence

Evidence

Operational Status

Behaviour

Signal

Avoid generic alternatives such as:

User

Report

Result

Score

Information

Data

Consistency strengthens the Oracle identity.

---

# Accessibility

Oracle should remain accessible.

High contrast.

Readable typography.

Clear hierarchy.

Keyboard navigation.

Colour should never be the sole indicator of state.

---

# Responsive Design

Oracle should scale across:

Desktop

Tablet

Mobile

Future native applications

Layouts should adapt without changing Oracle's visual identity.

# Design Review Checklist

Before approving any interface ask:

Does it answer one question?

Does it communicate intelligence?

Does it feel premium?

Does it match Oracle?

Can it be simplified?

Does animation improve understanding?

Can the component be reused?

If the answer to any question is uncertain, review the design again.

The Oracle Design System exists to create one consistent experience across every product, every game and every future platform.
