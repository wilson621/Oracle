# Sprint 30.5 Stage 2 Requalification R3 — Failed Attempt Analysis

**Classification:** Read-only forensic analysis and bounded harness correction
**Authority:** `authority-r3-20260731T163246422Z-00000000`
**Attempt:** `r3-20260731T163246422Z-00000000`
**Result:** Failed and permanently immutable

## Root causes

The approved machine contains Node.js `24.18.0` at
`C:\Program Files\nodejs\node.exe`, npm `11.16.0`, `npm.cmd`, and the canonical
npm CLI at
`C:\Program Files\nodejs\node_modules\npm\bin\npm-cli.js`. The R3 executor
resolved npm exclusively from `process.env.npm_execpath`. R3 intentionally has
no package script and the attempt invoked the executor directly with Node, so
that npm-populated environment variable was absent. The failure was therefore
an executor integration defect, not a PATH, npm installation, npm.cmd,
Corepack, or installation-layout failure.

The attempt identity was generated by calling the static
`RandomNumberGenerator.Fill(byte[])` API from Windows PowerShell 5.1. That API
is absent from the installed .NET Framework surface. The resulting
`MethodNotFound` was non-terminating, the byte array retained its initial zero
values, and the external command continued to create the suffix `00000000`.
This was an identity-generation and error-semantics defect.

## Failed-attempt consistency

The authority record, attempt record, authority evidence copy and lifecycle
events agree on the exact authority, attempt, candidate and harness identities.
Lifecycle event `001-attempt-prepared.json` passed and
`999-failed.json` records the first failure at `attempt-prepared` with reason
`npm CLI entry point is unavailable.` No command was active and no certificate
existed, so certificate teardown was not required.

The preserved namespace contains only the authority record, attempt-creation
record, authority evidence copy, two lifecycle records and the expected empty
attempt directories. Their verified SHA-256 values are:

- authority record and evidence copy:
  `618b1f8f11e416d14bdfb040c23ad4381af95daf150e401d70f1bb000c8c1076`;
- attempt-creation record:
  `711b21998d35f68e286ea7488fe6a91b6fa584184c60579dfc68e9478746c22d`;
- `001-attempt-prepared.json`:
  `faecdf2f3a62c76b09469b582d55116eff5a4dee240fc981590007a77385cabc`;
- `999-failed.json`:
  `59badb4bc63a0cb0026d13f94b03ffe9b595d2bb53c13260e3c8b02d8cd633b8`.

There is no R3 repository evidence namespace, built
artifact, package, certificate, trust entry or private signing material. The
Oracle package count and exact R3 certificate count are zero, and the
repository was clean after the failed attempt.

The immutable attempt-creation record describes its lifecycle as `prepared`
and its execution authority as not authorised even though the enclosing
authority had been consumed for execution. The later lifecycle failure record
is authoritative and prevents a false pass, but the creation record is
semantically misleading. It is not changed. Future creation records explicitly
label themselves as initial state, bind the consumed authority, and defer
terminal state to the append-only lifecycle ledger. Future failures add a
create-only terminal outcome that binds the creation, authority and lifecycle
record hashes and records teardown and residue state.

## Corrections

- Resolve npm and npx from the exact npm package installed beside the exact
  Node executable; validate regular files, real paths, package name and locked
  version; invoke the CLI through Node while preserving exact command and
  argument evidence.
- Generate identity entropy with
  `RandomNumberGenerator.Create().GetBytes(byte[])` under StrictMode and
  terminating-error semantics; reject entropy errors, null, incorrect length,
  all-zero bytes and malformed identities without fallback or retry.
- Use one governed PowerShell wrapper to preflight the repository, mint one
  matching authority/attempt pair and invoke the internal executor once.
- Make future attempt-creation and terminal-failure records internally explicit
  and create-only. No historical record is rewritten.
