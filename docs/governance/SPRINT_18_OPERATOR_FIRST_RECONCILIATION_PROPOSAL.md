# Purpose

This document records the exact documentation amendments prepared for Founder
review and approved for application on 24 July 2026.

The amendments reconcile existing terminology with the approved doctrine:

- Oracle remains an Operator Intelligence Platform;
- games are performance environments, not Oracle's product identity;
- Observation, Evidence, Understanding and Memory are distinct;
- Trust precedes longitudinal Understanding;
- the approved maturity model is governance, not a strict runtime dependency;
  and
- no architectural layer or Programme ordering changes.

The Oracle Founding Charter already owns and correctly states Oracle's
institutional vision. No new authoritative Vision document is proposed.

# 1 — Oracle Platform Constitution

## Amendment Rationale

The Constitution currently begins with game-first mission and vision language,
while the higher-authority Founding Charter and Strategy already define Oracle
as an Operator Intelligence Platform. The proposed wording changes emphasis
without changing the four-layer model, ownership, External Companion boundary,
privacy, Fair Play or approved product scope.

This requires an explicit constitutional amendment because the Constitution is
Stable and is Oracle's highest product and architectural authority.

## Proposed Mission Statement

Replace:

> Oracle exists to understand games, understand players and deliver
> intelligent, context-aware assistance through a unified and extensible
> platform.

With:

> Oracle exists to develop trusted, explainable understanding of Operators and
> help them improve their judgment and capability across supported gaming
> environments.
>
> Games provide performance context. Oracle serves the Operator.

## Proposed Vision Statement

Replace:

> To augment every player's gaming experience through intelligent,
> context-aware assistance across every supported game.

With:

> To become the world's most trusted Operator Intelligence Platform: an
> enduring platform that helps Operators improve over time through safe,
> trusted and explainable intelligence across supported games and Oracle
> Applications.

## Proposed Oracle Identity Additions

Add to “Oracle is not”:

- a clip-review product
- a statistics platform
- a system that treats every observation as durable personal intelligence
- a generic human-surveillance platform

Add to “Oracle is”:

- an Operator Intelligence Platform
- a system for governed longitudinal understanding
- a system in which games provide performance context
- a system that separates Observation, Evidence, Understanding and Memory

Retain existing statements that Oracle is a universal gaming-intelligence
platform, understands supported games and operates as a safe independent
Companion. These describe scope and capability, not product primacy.

## Proposed New Core Principle

Insert after “Platform First”:

### Operator Intelligence Primacy

> The Operator is Oracle's durable subject. Games are performance environments
> that provide context, knowledge and permitted evidence.

Oracle must optimise for durable Operator agency, understanding and improvement
rather than isolated analysis, statistics, clips or game-specific feature
volume.

Game-specific meaning remains inside Game Integrations. Operator Intelligence
remains governed through explicit Services, Evidence, scope, confidence,
policy and lifecycle. This principle creates no new architectural layer and
does not make every game-derived pattern an Operator-wide trait.

Renumber later principles only if the approved amendment policy requires it.
Prefer a labelled insertion without renumbering to minimise historical churn.

## Proposed New Promotion Principle

Insert after “Privacy by Design”:

### Promotion Requires Authority

> Permission to observe is not permission to retain, infer or remember.

Observation, Evidence, Understanding and Memory are separate lifecycle stages.
Promotion between them requires explicit purpose, policy, consent where
applicable, provenance, scope, quality, eligibility and retention authority.

No engine, model, Application, Game Integration or presentation component may
promote information merely because it can access or generate it.

## Proposed Guiding Statement

Replace:

```text
Oracle understands games.

Oracle understands players.

Oracle delivers intelligence.
```

With:

```text
Oracle studies Operators.

Games provide performance context.

Oracle turns permitted evidence into explainable intelligence.
```

The Founder may retain “Oracle understands games” as a secondary capability
statement if desired. It should not precede the Operator in the constitutional
identity.

## Internal and Public-Facing Expression

Retain the internal architectural doctrine:

> Oracle studies Operators.

Internally, “studies” means that Oracle develops governed, longitudinal and
explainable Understanding from permitted and admitted Evidence. It does not
authorise continuous monitoring, indiscriminate collection or surveillance.

Public-facing wording should lead with Operator agency and benefit:

> Oracle helps Operators improve their judgment and capability through safe,
> trusted and explainable intelligence.

Public-facing descriptions may explain that Oracle learns from permitted
performance evidence over time, but must also make control, purpose and
limitations clear. “Oracle studies Operators” must not be used as an
unqualified marketing claim where it could reasonably imply covert or
unbounded surveillance.

This distinction changes expression, not architectural intent. Internally the
Operator remains Oracle's durable subject, and no public phrasing may recast
Oracle as a game analyser, clip-review application or statistics platform.

## Unchanged Constitutional Meaning

The amendment must explicitly preserve:

- Oracle Platform → Services → Applications → Game Integrations;
- Services before Applications;
- intelligence presentation independence;
- single ownership;
- immutable Context;
- assistance, never automation;
- External Companion architecture;
- safety before coverage;
- privacy by design;
- extension-first growth; and
- preservation of working product value.

# 2 — Oracle Strategy

## Amendment Rationale

Strategy already contains “The Operator Intelligence Platform,” places the
Operator at the durable centre and states that games contribute context and
knowledge. It requires only a concise maturity-model and lifecycle
clarification.

## Proposed New Section

Insert after “Strategic Thesis: The Operator Intelligence Platform”:

### Operator Intelligence Maturity Model

```text
Trust
    ↓
Permitted Observation
    ↓
Admitted Evidence
    ↓
Operator Understanding
    ↓
Selective Memory
    ↓
Behavioural Intelligence
    ↓
Guidance
    ↓
Outcome Reassessment
    ↓
Prediction
```

This sequence expresses Oracle's long-term product maturity and governance.
It is not a strict runtime dependency graph and does not require reordering the
Engineering Programme.

Each transition must earn authority:

- Trust governs whether optional processing may begin.
- Observation remains transient unless admitted.
- Evidence preserves source, purpose, provenance and scope.
- Understanding is governed, revisable and explainable.
- Memory retains selectively rather than storing everything.
- Behavioural Intelligence consumes approved projections.
- Guidance strengthens Operator judgment rather than replacing it.
- Reassessment measures outcomes and corrects Oracle.
- Prediction is earned through longitudinal evidence and honest confidence.

Games remain essential semantic contexts. They do not define Oracle's identity
or justify cross-game conclusions without approved portability evidence.

## Proposed Flywheel Reconciliation

Retain the existing Oracle Flywheel. Amend its first two stages to make the
promotion boundary explicit:

```text
Trust and permitted Observation
        ↓
Admitted Evidence and reviewed game knowledge
        ↓
Governed Operator Understanding
        ↓
Selective longitudinal Memory
        ↓
Explainable assistance and Operator action
        ↓
Outcome reassessment
        ↓
Deeper Understanding and better prediction
        ↺
```

No strategic horizon or delivery sequence changes.

# 3 — Oracle Architecture

## Amendment Rationale

Architecture correctly states that games do not define Oracle and that
Applications consume Services. Its opening and high-level diagrams remain
intelligence-runtime centric and do not yet make the trust and promotion
boundaries explicit.

The amendment describes the existing and approved target architecture. It does
not claim runtime activation.

## Proposed Architectural Vision

Replace the opening sentence:

> Oracle is the operating platform for gaming intelligence.

With:

> Oracle is the Operator Intelligence Platform for supported gaming
> environments.

Add:

> The Operator is Oracle's durable subject. Games provide performance context,
> semantics and reviewed knowledge through Game Integrations. Oracle builds
> longitudinal understanding only from permitted, admitted and governed
> information.

Retain:

- Games do not define Oracle.
- Games extend Oracle.
- Applications do not own intelligence.
- Applications consume Oracle Services.
- Services consume Platform capabilities.

## Proposed Architectural Principle

Insert before “Intelligence First”:

### Trust and Promotion First

Optional Observation, Evidence admission, Understanding eligibility and Memory
retention are separate decisions. No downstream system may bypass an upstream
trust or promotion boundary.

“Intelligence First” then means intelligence precedes presentation after the
applicable trust and eligibility gates; it does not mean intelligence precedes
Operator control.

## Proposed Operator Intelligence Lifecycle

Add before the runtime-specific High-Level Architecture:

```text
Authenticated Operator and approved policy
        ↓
Trust and purpose-specific control
        ↓
Permitted transient Observation
        ↓
Authoritative source truth
        ↓
Minimal admitted Evidence reference
        ↓
Candidate and declared Understanding
        ↓
Eligibility, explanation and scope
        ↓
Selective Memory
        ↓
Purpose-scoped Oracle Context
        ↓
Specialised Behavioural Intelligence
        ↓
Guidance and Operator action
        ↓
Outcome reassessment
        ↓
Prediction and longitudinal refinement
```

State immediately below:

- this is the governed product lifecycle;
- it is not the current production runtime;
- it does not require every engine to execute serially;
- later Sprint activation remains governed by the Engineering Programme; and
- Oracle Platform v0.9 still has runtime persistence disabled.

## Proposed Dual-Context Clarification

Add:

### Operator Understanding and Game Context

Oracle reasons across two different forms of context:

- **Operator Understanding** is longitudinal, personal, purpose-scoped,
  governed and revisable.
- **Game Context** is environmental, Session-bound or integration-scoped and
  interpreted by its Game Integration.

Neither absorbs the other. Game Context may support Operator Understanding only
through admitted Evidence and approved scope. Operator Understanding does not
grant shared Services authority to reinterpret game-specific meaning.

## Proposed Memory Clarification

Amend the Memory subsystem language:

> Governed Memory is selective retention, reassessment, decay and removal of
> eligible Understanding. The current `memoryEngine` derives a runtime pattern
> profile from historical Sessions and may later contribute candidate signals;
> it is not the durable Memory authority and its output is not automatically
> retained Understanding.

No implementation rename is included in this amendment.

## Proposed Legacy Compatibility Note

Add to Verified Integration Limits:

- the direct `analyseFight`, clip-upload, hard-coded Call of Duty Session,
  Combat Rating and game-statistics paths are legacy product paths;
- their continued presence does not make game analysis Oracle's architectural
  centre;
- they must not be expanded into new Operator Intelligence authority; and
- their migration belongs to later approved Session Intelligence and Unified
  Product Experience Sprints.

## Proposed Prediction Clarification

Add:

> The current Prediction Engine produces a bounded near-term performance
> forecast from existing Trend output. It must not be described as mature
> longitudinal Operator prediction until later governed Understanding,
> Guidance outcome and reassessment evidence exist.

# 4 — Oracle Engineering Programme

## Amendment Rationale

The Programme already preserves the approved order:

- trust before inference;
- Operator control before personalisation;
- Session authority before Evidence;
- Evidence before Understanding;
- Understanding before coaching; and
- reassessment before longitudinal improvement.

No Sprint, Epic, Gate or dependency reordering is required.

## Proposed Programme Additions

Add to Programme Principles:

1. The Operator is Oracle's durable subject; games are performance contexts.
2. Permission to observe does not imply Evidence admission, Understanding or
   Memory.
3. Memory is selective and policy-governed.
4. The Operator Intelligence maturity model is not a strict runtime dependency
   graph.

Numbering should be reconciled during the approved edit.

## Proposed Sprint 18 Clarification

Add to Sprint 18 Purpose:

> Sprint 18 establishes the control plane for future Observation purposes
> without implementing Observation. It ensures that no later Observation,
> Evidence, Understanding or Memory capability can bypass purpose-specific
> consent, inspection, correction, dispute, retention and deletion control.

Add to Sprint 18 Deliverables:

- future-compatible purpose and observation-category control semantics;
- visibility of lifecycle stage and retention state in the Trust Centre; and
- proof that Observation permission, Evidence admission, Understanding
  eligibility and Memory retention remain distinct.

Add to Sprint 18 exclusions:

- observation capture;
- automatic Evidence admission;
- Understanding accumulation;
- Memory promotion;
- Behavioural Intelligence;
- Guidance and Prediction.

These additions clarify existing scope and must not absorb Sprints 21–24 or 26.

## Proposed Prediction Note

Add to Sprint 23:

> Sprint 23 Prediction is a bounded Session and Trend forecast. Mature
> outcome-informed longitudinal prediction compounds through later Guidance
> and reassessment; this distinction does not reorder the Programme.
